# 2026-10-29 大批量处理与性能测量优化

本轮基于 1.0.2 源码实施，未改变版本号、签名或发布发行版。工作区改动尚未提交、推送。

## 已实现

- **历史显示窗口**：按 `(createdAt,id)` 稳定排序，每次增加 100 条，单窗最多 500 条；之后明确进入较早窗口，支持返回较新/最新窗口。SQL 最多取 501 条以判断下一页；数据库通知在查询前合并。选择 ID 可跨窗保留，动作按 ID 重新获取记录，日期删除仍覆盖当前窗口之外的同日记录。筛选变化回到最新窗口。
- **原图状态缓存**：不可用/已回收结果短期缓存 15 秒；回前台、手动刷新和重关联可立即刷新。请求带 generation，旧异步结果不能覆盖新 URI 或刷新结果。缓存只保留当前窗口和跨窗选择；真实回收请求仍实时检查。
- **队列增量持久化**：增加 ID/URI 索引，writer 只比较脏记录与已成功落盘值，删除记录同样带 revision。旧写入完成不能清除期间产生的新修改；失败可由后续 flush 重试。保留不可变列表、排序、撤销、迟到 probe 防护和检查点。列表快照复制和 StateFlow 等值比较仍有 O(N) 成本，不宣称单项更新整体达到 O(1)。
- **JPEG 独立探测**：64 KiB 分块扫描，最多保留 1 MiB 原始头部，复用 pinned UHDR 的 JPEG 扫描与元数据 parser。HDR 在第二幅 JPEG EOI 后停止；SDR 仍扫描尾部以保持原识别语义。异常、超限或不可 seek 时回退原解析；完整转码解码路径不变，增益图未缩小或重建。
- **性能测量**：加入默认关闭的 Kotlin/原生分阶段日志和独立 QA 采集脚本，保留原始数据及历史 `durationMs` 语义。新增 Macrobenchmark 和 Profile 生成变体；当前只覆盖启动与导航，尚未用真机生成 Profile 替换现有手写规则。
- **可靠性与 CI**：新增有多种历史/任务/替换状态的 v5→v6 磁盘数据库测试、真实进程结束后的事务/队列恢复编排。GitHub workflow 对受信任分支执行快速检查，完整原生验证需手动选择专用 macOS ARM64 runner；保留 Gitea 配置，没有自动发布。

操作命令与采样边界见 [性能测量说明](../PERFORMANCE.md)。

## JPEG 探测的主机测量

WSL x86-64 Release 构建，给小尺寸 JPEG 追加 **64 MiB 合成尾部**，两种路径分别在独立进程执行，使用 `/usr/bin/time -v` 记录最大 RSS；每项三次，表内保留三次原始值和中位数。新路径测试调用公开 `probeImage`，并断言实际进入 bounded 路径、没有整读回退。

| 样本与路径 | 最大 RSS 三次原始值（KiB） | 中位数（KiB） | 新路径实际读取（B） |
| --- | --- | ---: | ---: |
| HDR 384×512，原路径 | 137664 / 137860 / 137792 | 137792 | — |
| HDR 384×512，新路径 | 7316 / 7076 / 7184 | 7184 | 87057 |
| SDR 96×64，原路径 | 137172 / 137152 / 136868 | 137152 | — |
| SDR 96×64，新路径 | 6900 / 6908 / 6840 | 6900 | 67125897 |

这是**合成尾部样本的独立探测 RSS**，不是手机 PSS、全分辨率转码内存或整批提速。SDR 仍扫描整尾部，不能把它描述为避免读取视频尾部。实际读取字节包含签名读取等操作，可能略大于文件长度。

当前不调整编码并发、安全预算、默认质量或相册兼容规则。直接返回 Bitmap 的预览路径和按实际解码尺寸校准内存预算，仍需先取得对应真机测量。
